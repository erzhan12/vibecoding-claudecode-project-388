# Трекер цен с Claude


[![hexlet-check](https://github.com/erzhan12/vibecoding-claudecode-project-388/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/erzhan12/vibecoding-claudecode-project-388/actions)

Трекер цен на Claude Code: следит за семью ноутбуками на Kaspi.kz и присылает в Telegram только значимые изменения.

Учебный проект Хекслета: https://ru.hexlet.io/programs/vibecoding-claudecode

## Ниша и цель

Ниша — ноутбуки в Kaspi Магазине (Алматы). Цель — поймать момент, когда на
нужную модель появится скидка, и купить выгоднее. Трекер проверяет семь
карточек товаров, сравнивает цены с прошлой проверкой и сообщает только о том,
что важно для покупки: заметное изменение цены, начало или конец скидки,
появление или пропажа рассрочки, наличие товара.

Список товаров — в разделе «Отслеживаемые ноутбуки» [`TASK.md`](TASK.md).

## Стек

- Claude Code Skills — скилл `tracker` (оркестрация прогона) и скилл `extract-price` (цены и рассрочка по одной карточке)
- Агент `telegram-summary` на Haiku — только оформляет текст сводки из готового списка изменений, без инструментов
- Python 3 со стандартной библиотекой — `send.py` и расчёт цен, тесты через `unittest`; внешних зависимостей нет
- GitHub MCP — чтение и запись снимков цен в приватный репозиторий `erzhan12/tracker-data`
- Telegram Bot API — отправка сводки через `send.py`
- Kaspi.kz — HTML карточки товара и каталожный endpoint (запросы через `curl`)

## Установка

```bash
git clone https://github.com/erzhan12/vibecoding-claudecode-project-388.git
cd vibecoding-claudecode-project-388
```

Устанавливать пакеты не нужно: нужны Python 3, `curl` и Claude Code.

Для работы трекера нужны:

- Telegram-бот и чат, куда он пишет: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`;
- доступ на запись к приватному репозиторию `erzhan12/tracker-data` (туда сохраняются снимки).

> **Секреты.** Значения токенов и ID чата храните только в переменных окружения
> или в локальном `.env`. Не коммитьте их, не вставляйте в чат с агентом и не
> передавайте в аргументах команд. В Telegram отправляет только `send.py`.

### Облачный Claude Code

В настройках облачного окружения (environment):

1. **Переменные окружения** — задайте имена ниже, значения вводите только в настройках окружения:

   | Переменная | Зачем |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | токен Telegram-бота для `send.py` |
   | `TELEGRAM_CHAT_ID` | ID чата, куда приходит сводка |

2. **Доступ к сети** — разрешите хосты:

   | Хост | Зачем |
   |---|---|
   | `kaspi.kz` | карточки товаров и каталожный endpoint |
   | `api.telegram.org` | отправка сводки |

3. **Репозиторий для снимков** — добавьте в сессию `erzhan12/tracker-data` с правом записи.
   Снимки пишутся через встроенную GitHub-интеграцию сессии, `GITHUB_PAT` в облаке не нужен.

Подробнее про облачные окружения: https://code.claude.com/docs/en/claude-code-on-the-web

### Локальный запуск: файл `.env`

Альтернатива переменным окружения — файл `.env` в корне проекта (он в
`.gitignore`, не коммитьте его). Переменные окружения важнее `.env`.

```dotenv
TELEGRAM_BOT_TOKEN=<токен бота>
TELEGRAM_CHAT_ID=<id чата>
```

Для записи снимков локально используется GitHub MCP-сервер из [`.mcp.json`](.mcp.json):
задайте переменную окружения `GITHUB_PAT` (токен с доступом к `erzhan12/tracker-data`)
и одобрите сервер `github` для проекта, например
`"enabledMcpjsonServers": ["github"]` в незакоммиченном `.claude/settings.local.json`.

## Использование

Откройте проект в Claude Code и попросите:

```text
запусти трекер
```

Трекер запускается вручную по такому запросу; автоматического запуска по
расписанию в проекте нет.

Что происходит за один прогон (скилл [`tracker`](.claude/skills/tracker/SKILL.md)):

1. **Сбор цен.** Для каждой из семи ссылок скилл `extract-price` достаёт цены и рассрочку. Ошибка по одному товару (например, нет в наличии) не останавливает прогон — товар попадает в таблицу строкой с ошибкой.
2. **Сравнение с предыдущим снимком.** Последний снимок `YYYY-MM-DD.json` читается из `erzhan12/tracker-data`, изменения считаются по каждому товару и фильтруются по правилам [`KNOWLEDGE.md`](KNOWLEDGE.md). Мелкие колебания отбрасываются.
3. **Telegram — только при значимых изменениях.** Если они есть, агент `telegram-summary` пишет короткую сводку, а `send.py` отправляет её. Если значимых изменений нет (или это первый запуск), в Telegram ничего не уходит.
4. **Сохранение снимка.** Таблица прогона сохраняется в приватный `erzhan12/tracker-data` как `YYYY-MM-DD.json` (дата по Алматы). Повторный прогон в тот же день перезаписывает файл дня.

Порог изменения цены, правила для скидки, рассрочки и наличия описаны только в
[`KNOWLEDGE.md`](KNOWLEDGE.md) — меняйте поведение трекера там.

Цену одной карточки можно проверить отдельно: попросите Claude «проверь цену» и
дайте ссылку `kaspi.kz/shop/p/...` (скилл [`extract-price`](.claude/skills/extract-price/SKILL.md)).

### Поля результата

Полный контракт — в [`TASK.md`](TASK.md). Kaspi отдаёт `price` (за сколько товар
продаётся сейчас) и `unitPriceBeforeDiscount` (цена до скидки); из них считаются:

| Поле | Значение |
|---|---|
| `regular_price` | Цена без скидки: `unitPriceBeforeDiscount`, если он больше `price`; иначе `price`. |
| `sale_price` | Цена со скидкой: `price`, если `unitPriceBeforeDiscount` больше `price`; иначе `null` — скидки нет. Текущая цена покупки — `sale_price`, а если он `null`, то `regular_price`. |
| `has_credit` | Есть ли рассрочка: `true` / `false` из поля `loanAvailable`. |

`has_credit` берётся из **неофициального** каталожного endpoint Kaspi
(`/yml/product-view/pl/results`), а не со страницы товара. Этот endpoint не
документирован и может измениться или перестать отвечать. Если запрос не
удался, `has_credit` равен `null`: цены при этом всё равно возвращаются, а
переход в `null` и обратно не считается значимым изменением.

Если товар проверить не удалось (например, нет в наличии), вместо цен
возвращается `{"error": "<причина>", "url": "<ссылка>"}`.

### Отправка в Telegram: `send.py`

Скилл `tracker` вызывает его сам, но скрипт можно запустить и вручную:

```bash
python3 send.py "текст сообщения"
```

Настройки — `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` из окружения или `.env`
(см. «Установка»). При успехе печатает `Отправлено.`; при отсутствии текста или
настроек — ошибку и код выхода 2; при ошибке сети или Telegram API — ошибку и
код 1. Токен в сообщения об ошибках не попадает.

### Тесты

Без сети и без реальной отправки:

```bash
python3 -m unittest discover -s tests -v
```

Живая проверка агента `telegram-summary` на Haiku (платно, нужен залогиненный `claude`, в Telegram ничего не отправляет):

```bash
RUN_HAIKU_SUMMARY=1 python3 -m unittest tests.test_telegram_summary -v
```

Структура проекта и правила для ИИ-агентов — в [`AGENTS.md`](AGENTS.md).
